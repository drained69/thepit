# The Pit — audit and hardening, 2026-11-08

**Mainnet readiness: blocked.** This source review found and fixed concrete
security and reliability issues. Remaining High findings prevent treating this
version as safe for real funds. Passing tests are evidence for the covered
behavior, not a guarantee of safety or an independent audit certification.

Scope: Pit/factory contracts, cross-chain funding and rNEAR wallet UI, wallet
selection, funding proxy/static server, brain ledger/proof service, gate, and
web dependency review. Changes from this pass are local and have not been
published to Railway or NEAR. The previously deployed funding panel and its
server credential are separate from these new changes. No funded transfer,
paid inference request, or production contract upgrade was performed.

The supplied Plamen orchestration/reference files were unavailable under
`~/.Codex/rules` and no NEAR-specific prompt was provided there. Review used
parallel contract, frontend and service code review, targeted regression tests,
randomized accounting tests, dependency advisories and local NEAR sandbox runs.
No assertion is made that every file or attack path has been exhaustively covered.

## Changes made

| Area | Fixed behavior and impact |
|---|---|
| Pool accounting — High | Unresolved staking operations stay locked instead of timing out and overlapping late callbacks. |
| Pool views — Medium | Another account's staking position cannot enter reserve accounting. |
| Factory — Medium | Invalid immutable curve defaults and duplicate pools are rejected before a factory becomes unusable. |
| Funding — Medium | Quote and immutable SDK build context must match the exact source/destination accounts, networks, assets, amount, slippage and freshness before execution and every signature. |
| Funding recovery — Medium | Ambiguous broadcasts retain a recovery attempt before signing; restored state is validated. Quote idempotency keys remain stable. |
| Wallet changes — Medium | EVM identity is rechecked after network selection; typed-data domain chain is checked. rNEAR transactions revalidate the signer after asynchronous SDK reads. |
| Brain budget — High | Inference reserves its budget durably before the potentially billable request; uncertain billing retains the reservation. |
| Ledger persistence — Medium | Private atomic writes with file/directory fsync; corrupt or unreadable existing ledgers fail closed. |
| Gate — Low/Medium | Strict buyer/epoch/field validation; mainnet refuses development identities and registries not requiring TEE attestation. |
| Services — Medium | Bounded HTTP waits, bounded retained proof-cache bytes, and numeric configuration validation. |
| Funding API — Medium | Bounded request/response sizes, concurrent upstream requests, allowed queries, payload shapes, origin checks, and idempotency header validation. Upstream failures are sanitized. |
| Static server — Medium | Malformed URI decoding no longer rejects an unhandled async callback; path containment, missing-asset 404s, method/HEAD handling, stream errors and HTTP timeouts are handled. |
| Wallet lifecycle — Low | Concurrent initialization shares one promise; disposed subscriptions cannot attach later, and active wallet selection is not cached across wallet changes. |

## Performance and maintenance

- Directional token lists cache for 60 seconds and simultaneous identical loads
  share one request. Quotes and order status are never cached. Cache keys are
  limited to the three supported EVM source lists and NEAR destination list.
- Funding upstream concurrency is capped at eight; decoded responses at 4 MiB;
  request bodies at 64 KiB. Rate-limit bucket expiry sweeps run periodically,
  rather than scanning every bucket on every request.
- Source-token selection searches by symbol/address and renders at most 100
  matches plus an existing selection, rather than over 2,000 options at once.
  Tokens retain their provider identities; they are not merged by symbol.
- Static file metadata uses asynchronous filesystem calls. Immutable built assets
  retain long cache lifetimes; API responses and errors are not cached publicly.
- Added `npm --prefix webapp test` with a TypeScript loader for supported Node
  versions; production minimum is now documented as Node 20.11.
- Upgraded Vite from 5.4 to the 6.4.5 security line and direct bn.js to 5.2.5.
  Vite lists 6.4 as a security-supported branch: https://vite.dev/releases.
  The last install audit reports **six Moderate advisories, no High/Critical**.
- A wallet-selector 8.10.2 / near-api-js 5 upgrade was evaluated in an isolated
  temporary dependency tree and rejected: it introduced High base-x transitive
  findings. No forced incompatible peer overrides were applied. Wallet-selector
  and legacy NEAR API Moderate advisories remain to resolve through a reviewed
  wallet-library migration. The large legacy wallet/NEAR bundle remains a
  performance limitation; the build still reports a chunk above 500 KiB.

## Remaining launch blockers

| Priority | Finding | Required resolution |
|---|---|---|
| High | A failed or unknown-outcome head ticket can obstruct the bounded payout scan beyond the first ten IDs. | Independent bounded traversal, fair liquidity scheduling, and confirmed-outcome recipient recovery with migration tests. |
| High | Harvest, agent-pass and other refunds still use detached transfers without durable recovery. | A reviewed common transfer-claim state machine; earned counters must reflect confirmed outcomes. |
| High / production | Inference accounting still depends on a single local writer and configured exchange rates. | A persistent volume and one replica at minimum, plus provider-charge/NEAR-receipt reconciliation. Atomic files alone are not a distributed payment ledger. |
| Medium / product | Gate challenges are machine-readable and Sybil-prone; another caller can exhaust a buyer's session allowance. | Authenticate wallet ownership at issuance and integrate a specified anti-Sybil policy. Remove bot-proof guarantees meanwhile. |
| Medium / trust | JSON report/key association is not full hardware TDX attestation verification. | Verify measurements, collateral/revocation, certificate chain and provenance against a defined policy. |
| Production | Missing pool callbacks now safely retain the lock but can stop rebalancing indefinitely. | Verified operation/receipt reconciliation; never blind timeout unlocking. |
| Production | rNEAR reserve adapter is disabled and not interoperably verified. | Storage registration and actual stake/unstake/withdraw accounting tests against RHEA before enabling. |
| Production | Contract/ticket migration and final pinned WASM hash have not been released. | Review migration for any existing stored tickets and rehearse deployment using the final audited artifacts. |

Public API rate limits trust socket addresses, not client-controlled forwarding
headers. Behind a reverse proxy multiple users may share a limit; production
needs trusted edge per-client limits and abuse controls. The proxy uses a shared
server credential and is not a wallet-authenticated user entitlement service.
Browser order storage cannot prevent cross-device duplicates. A broadcast with
no returned order identifier needs manual source-wallet inspection.
